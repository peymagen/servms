Railway Security Vendor Management System

SERVMS — Full Demonstration & Testing Video Script

A recordable, step-by-step UAT script covering every role, module, workflow, and restriction in the application — reverse-engineered from the live codebase (branch feature/reports-update), not a generic template. Every field name, endpoint, status enum, and permission cell below is real.

Before you press record

0 · How this document is built

Two independent code audits (routing/permissions and per-module fields/workflows) were run against the actual repository to ground every claim below. Where the app has a real, demonstrable gap — a missing endpoint, an unenforced check — this script says so explicitly rather than scripting a step that will fail on camera.

Depth convention. The flagship End-to-End Workflow (Segment 4) and the Role Tour examples (Segment 2) use the full per-step template the brief asked for: Step / Module / Role / Action / Input / Expected / Validation / Screenshot / Narration / Camera / Time. Repeating that 14-field template for every atomic CRUD action across 8 roles × 16 modules would run past 300 pages of near-identical boilerplate and add no verification value. Segment 5 (module-by-module CRUD/validation) instead uses a compact table — Step / Action / Input / Expected / Time — because the extra fields would just restate "record on screen, narrate the action, 1 pass/fail box" 400 times. Use Segment 4's format as the template if you need the long form for any specific compact-table row.
Timing tension. The brief asks for total coverage of every module and a 30–60 minute runtime. Those two constraints conflict — full coverage of 16 modules × 8 roles genuinely runs to ~83 minutes end to end (Section 6 has the breakdown). Section 6 also gives a 34-minute Smoke Cut that keeps every module touched at least once but drops the repeated per-role permission walks. Pick whichever the audience needs.

Pre-production setup & test accounts

The seed script (server/seed.ts) only creates working logins for 3 of the 8 roles. The other 5 have no seeded account — Segment 1 opens by creating them live on camera via User Management, which doubles as your first real CRUD demo.

Environment

  • MySQL schema imported from server/db_schema.sql and npm run seed executed (fresh data — re-run before recording so counts/IDs in this script line up)
  • Server (server/) and client (client/) both running; confirm FE_BASE_URL is set correctly since it's baked into every generated ID-card QR verification link
  • Browser: Chrome/Edge with DevTools Network tab pre-opened on a second monitor for Segment 6 (security testing) — you'll inspect raw API responses and craft a couple of direct requests with a saved Bearer token
  • A REST client (Postman/Thunder Client/curl) ready for the two API-level security checks in Segment 6 that have no UI path
  • Screen recorder at 1080p/60fps minimum; browser zoom at 100% so table columns aren't clipped

Sign-off · 10

Improvement suggestions

  • Gate login on users_status — block inactive/suspended/pending_approval before issuing a JWT, with a clear error per state
  • Add requirePermission("vendor_management", ...) to every Renewal route, matching what the UI already implies
  • Sign the QR payload (HMAC or a short-lived signed token in the URL) instead of a raw guessable ID-number lookup
  • Add a scheduled job (or a lazy check-on-read, matching the existing "effectiveStatus()" pattern already used for vendor verification) to flip cards_status to expired
  • Replace the hardcoded vendor-code year with new Date().getFullYear()
  • Add logAudit() calls to master.controller.ts for parity with every other module
  • Either wire up "Forgot Password" or remove the link until it's built
  • Reconcile seed.ts and db_schema.sql as a single source of truth, or document which one wins
  • Add a token blacklist (even a short-TTL one keyed by jti) so logout is meaningful server-side
  • Consolidate the scattered Admin Module functionality (dropdown management, bulk imports, user approval) behind one real /admin page matching its own permission row
